## 0. Критическое ограничение: 24-часовое окно

**Прочитать до начала сборки.** Это единственное место, где моя исходная спецификация
требует правки, и оно ломает сценарии у большинства новичков в ManyChat.

Meta разрешает писать пользователю свободно только **24 часа с его последнего сообщения**.
После этого стандартная отправка блокируется, ManyChat покажет ошибку доставки.

Что это значит для дожима из `CHATBOT-SPEC.md` (S8):

| Касание | Внутри окна? | Как реализовать в ManyChat |
|---|---|---|
| **15 минут** | ✅ да | Smart Delay 15 min — работает как есть |
| **24 часа** | ⚠️ на границе | Ставить **Smart Delay 23 hours**, не 24. Иначе отправка упрётся в закрытое окно |
| **72 часа** | ❌ нет | Стандартно **не отправится**. Нужен один из обходов ниже |

### Легальные способы дотянуться после 24 часов

1. **Recurring Notifications (рекомендую).** Meta даёт пользователю кнопку-подписку
   «получать сообщения». В ManyChat это шаг `Recurring Notification`. Человек нажимает —
   и вы можете писать ему по расписанию вне окна. Идеально ложится на сезонный продукт:
   подписка «сообщить, когда откроются смены».
2. **Human Agent tag — 7 дней.** Действует, только когда отвечает **живой человек** из
   Live Chat, не автоматика. Годится для «менеджер вернулся с ответом», не для дожима.
3. **Платная реклама вместо сообщения.** Человек уже попал в аудиторию
   `BoF · Messenger Openers · 365d` (`120253645313910709`) — дожимайте его ретаргет-кампанией
   `120253645419140709`, а не сообщением. Это и есть та связка, ради которой мы её собирали.

**Итог:** 72-часовое касание из спецификации переносим в рекламу, а не в бота.
Внутри бота остаётся 15 минут и 23 часа.

## 1. Custom Fields (Settings → Fields → User Fields)

Создать до сборки флоу — иначе шаги User Input некуда сохранять.

| Название поля | Тип | Назначение |
|---|---|---|
| `child_age` | Number | Возраст ребёнка. Основа всей развилки S1 |
| `child_name` | Text | Имя ребёнка |
| `parent_name` | Text | Имя родителя |
| `parent_phone` | Text | Телефон (валидация — см. раздел 5) |
| `city` | Text | Город — для трансфера |
| `chosen_session` | Text | Выбранная смена |
| `lang` | Text | `ru` или `ro` |
| `entry_keyword` | Text | Каким словом вошёл: МЕСТО / ХОЧУ / ЛЕТО / VREAU / LOC |
| `entry_hour` | Number | Час начала диалога (для сверки с почасовой статистикой кабинета) |
| `drop_reason` | Text | **Причина отвала** — главное поле проекта |
| `last_state` | Text | Последнее состояние: S1 / S2 / S3 / S5 / S7 |
| `handed_to_manager` | Boolean | Передан ли менеджеру |

> `drop_reason` заполняется **до** каждого рискованного шага, а не после.
> Логика: перед выдачей цены ставим `drop_reason = price_shock`; если человек продолжил —
> перезаписываем на следующее значение. Тот, кто отвалился, останется с последним
> проставленным значением. Иначе причину отвала вы никогда не узнаете —
> молчащий пользователь ничего не нажмёт.

### Значения `drop_reason`

`age_out_of_range` · `price_shock` · `no_free_dates` · `slow_reply_night` ·
`went_silent_S1` · `went_silent_S2` · `went_silent_S3` · `converted`

## 2. Tags (Settings → Tags)

| Тег | Когда ставить |
|---|---|
| `lang_ru` / `lang_ro` | Сразу после определения языка |
| `qualified_9_18` | Возраст прошёл фильтр |
| `rejected_age` | Возраст вне диапазона |
| `waitlist_next_season` | Согласился на уведомление о следующем сезоне |
| `price_shown` | Увидел цену |
| `booking_started` | Дошёл до S5 |
| `booking_data_complete` | Все данные собраны |
| `sent_to_manager` | Передан в Live Chat |
| `objection_price` / `objection_fear` / `objection_distance` | Какое возражение высказал |

Теги нужны не для красоты: по ним вы потом соберёте аудитории и поймёте,
на каком шаге теряются деньги.

## 3. Триггеры входа

### 3.1 Keywords (Automation → Keywords)

Реклама просит написать конкретное слово — бот обязан его узнавать.
Создать **одно правило на язык**, режим совпадения — `contains` (не `is`),
иначе «хочу место» или «Хочу!» не сработают.

| Правило | Ключевые слова | Ведёт в Flow |
|---|---|---|
| Вход RU | `МЕСТО`, `ХОЧУ`, `ЛЕТО`, `место`, `хочу`, `лето` | `01 · Вход RU` |
| Вход RO | `LOC`, `VREAU`, `loc`, `vreau` | `01 · Вход RO` |

Добавить типичные опечатки и латиницу: `mesto`, `hochu`, `leto`.

> ⚠️ **Правило на будущее:** если в новом креативе появится другое кодовое слово,
> его надо завести в ManyChat **до** запуска объявления. Иначе платный трафик придёт
> в Default Reply.

### 3.2 Ref URL — и заодно решение проблемы с аналитикой

Сейчас в объявлениях ретаргета стоит `link_url = https://m.me/287227294469844` —
это «голая» ссылка, ManyChat не поймёт, из какого объявления пришёл человек.

Создайте **Growth Tool → Ref URL** и меняйте ссылку в креативах на вид:

```
https://m.me/287227294469844?ref=bof_ru
https://m.me/287227294469844?ref=bof_ro
https://m.me/287227294469844?ref=tof_ru
https://m.me/287227294469844?ref=tof_ro
```

Что это даёт:
- бот здоровается **сам**, не дожидаясь, пока человек напечатает слово — минус один шаг отвала;
- в `entry_keyword` пишется источник, и вы наконец видите, **какое объявление приносит бронь,
  а не просто переписку**.

Это прямо закрывает дыру из аудита: у кабинета 0 пикселей и 5 исходящих кликов за 30 дней,
сквозной аналитики нет вообще. Логи ManyChat — единственный доступный вам источник правды
о том, что происходит после клика.

### 3.3 Default Reply

Обязательно настроить. Сюда попадут все, кто написал не ключевым словом
(«сколько стоит?», «здравствуйте», «есть места?»).

Логика Default Reply: **не игнорировать вопрос**, ответить на него и увести в S1.
Ни в коем случае не «Я вас не понял».

## 4. Структура Flows

Не делать один гигантский флоу. Разбить так:

```
01 · Вход RU                    ← Keyword + Ref URL
02 · Вход RO                    ← Keyword + Ref URL
03 · S1 Возраст RU
04 · S1 Возраст RO
05 · S1-X Отказ по возрасту (RU/RO в одном, через Condition)
06 · S2–S3 Смены и цена RU
07 · S2–S3 Смены и цена RO
08 · S4 FAQ RU                  ← меню вопросов
09 · S4 FAQ RO
10 · S6 Возражения RU
11 · S6 Возражения RO
12 · S5 Бронь RU
13 · S5 Бронь RO
14 · S7 Передача менеджеру      ← общий, язык через Condition
15 · S8 Дожим 15 мин            ← Smart Delay
16 · S8 Дожим 23 часа           ← Smart Delay
17 · Recurring Notification     ← подписка на следующий сезон
18 · Пограничные случаи         ← голосовые, эмодзи, мат, не тот язык
```

Причина дробления: ManyChat неудобно отлаживать в длинных полотнах, а языковые ветки
всё равно расходятся почти полностью.

## 5. Сборка ключевых Flow — по шагам

### Flow `01 · Вход RU`

| # | Тип шага | Содержание |
|---|---|---|
| 1 | Action | `Set Custom Field` → `lang = ru` |
| 2 | Action | `Add Tag` → `lang_ru` |
| 3 | Action | `Set Custom Field` → `entry_keyword = {{last_input}}` |
| 4 | Action | `Set Custom Field` → `entry_hour` (час подключить через дату/время системы) |
| 5 | Action | `Set Custom Field` → `drop_reason = went_silent_S1` |
| 6 | Action | `Set Custom Field` → `last_state = S1` |
| 7 | Send Message | Текст S0 из `CHATBOT-SPEC.md` |
| 8 | User Input | Тип **Number** → сохранить в `child_age`, «Сколько лет ребёнку?» |
| 9 | Go to Flow | `03 · S1 Возраст RU` |

> Шаг 8 обязательно типа **Number**, а не Text — иначе условие по возрасту не сработает.
> В настройках User Input задать сообщение при неверном вводе: «Напиши, пожалуйста, цифрой —
> например, 12».

### Flow `03 · S1 Возраст RU` — развилка

| # | Тип шага | Логика |
|---|---|---|
| 1 | **Condition** | `child_age` **is greater or equal** 9 **AND** `child_age` **is less or equal** 18 |
| 2a | ✅ Да → Action | `Add Tag` → `qualified_9_18` · `drop_reason = went_silent_S2` · `last_state = S2` |
| 2b | ✅ Да → Send Message | Подтверждение возраста + вопрос про смену (текст S1 из спецификации) |
| 2c | ✅ Да → Go to Flow | `06 · S2–S3 Смены и цена RU` |
| 3a | ❌ Нет → Action | `Add Tag` → `rejected_age` · `drop_reason = age_out_of_range` |
| 3b | ❌ Нет → Go to Flow | `05 · S1-X Отказ по возрасту` |

### Flow `05 · S1-X Отказ по возрасту`

Внутри — вложенный Condition: `child_age < 9` → текст про «младше не берём»,
иначе → текст про «после 18».

Обязательно закончить шагом **Recurring Notification** («написать, когда откроем набор
на следующий сезон») и тегом `waitlist_next_season`. Это единственный законный способ
вернуться к этому человеку через полгода.

### Flow `06 · S2–S3 Смены и цена RU`

| # | Тип шага | Содержание |
|---|---|---|
| 1 | Send Message + Quick Replies | Список свободных смен. По кнопке на каждую смену |
| 2 | Action | `Set Custom Field` → `chosen_session` = выбранная смена |
| 3 | Action | `drop_reason = price_shock` · `last_state = S3` |
| 4 | Send Message | Карточка S3: цена + что входит + остаток мест |
| 5 | Action | `Add Tag` → `price_shown` |
| 6 | Quick Replies | `Бронирую` → Flow 12 · `Вопрос` → Flow 08 · `Дорого` → Flow 10 |
| 7 | Smart Delay | 15 минут → Flow 15 (дожим), если не было ответа |

> Порядок шагов 3 и 4 принципиален: `drop_reason = price_shock` ставится **перед**
> показом цены. Кто испугался — отвалится уже помеченным.

### Flow `12 · S5 Бронь RU`

Собирать по одному полю за шаг, каждый — отдельный **User Input**:

| # | Поле | Тип User Input | Валидация |
|---|---|---|---|
| 1 | `child_name` | Text | — |
| 2 | `parent_name` | Text | — |
| 3 | `parent_phone` | **Phone** | Встроенная в ManyChat |
| 4 | `city` | Text | — |

Далее:
- Action: `Add Tag` → `booking_data_complete`, `drop_reason = converted`, `last_state = S5`
- Send Message: финальное подтверждение из спецификации
- Action: **Notify Admin** — уведомление менеджеру
- Go to Flow: `14 · Передача менеджеру`

### Flow `14 · S7 Передача менеджеру`

| # | Тип шага | Содержание |
|---|---|---|
| 1 | Condition | Рабочее время? (по расписанию менеджера) |
| 2a | ✅ Да → Send Message | «Сейчас подключу менеджера…» |
| 2b | ❌ Нет → Send Message | «Менеджер на связи с {{рабочие_часы}}…» + предложить задать вопрос боту |
| 3 | Action | `Notify Admin` (и/или Email/Telegram-уведомление) |
| 4 | Action | `Add Tag` → `sent_to_manager`, `handed_to_manager = true` |
| 5 | Action | **Pause Automation** |

> Шаг 5 обязателен. Без `Pause Automation` бот продолжит писать поверх живого менеджера —
> это выглядит грубо и рушит сделку.

## 6. Live Chat: настройка

1. **Inbox → Live Chat.** Назначить ответственных.
2. Включить уведомления на телефон — иначе «менеджер ответит за 15 минут» станет ложью,
   а это обещание бот даёт в тексте.
3. Настроить **Human Agent tag**, чтобы менеджер мог отвечать в течение 7 дней,
   а не 24 часов.
4. Договориться о правиле: после ответа менеджера — снять `Pause Automation` вручную,
   иначе клиент навсегда выпадет из автоматики.

## 7. Пограничные случаи (Flow 18)

| Ситуация | Реализация в ManyChat |
|---|---|
| Голосовое сообщение | Условие по типу вложения → текст «Не могу послушать голосовое 🙈» |
| Только эмодзи / стикер | Default Reply → повтор последнего вопроса |
| Не RU/RO | Английский шаблон → `14 · Передача менеджеру` |
| Мат, агрессия | Keyword-правило со стоп-словами → нейтральный ответ + `Pause Automation` |
| Спам, ссылки | Тег `spam`, без ответа, менеджеру не передавать |
| Вернулся через месяцы | Condition по `chosen_session` — если поле заполнено, начинать не с нуля |

## 9. Что смотреть в первые две недели

ManyChat → Audience, фильтры по тегам:

| Вопрос | Как посмотреть |
|---|---|
| Сколько отваливается по возрасту | Доля тега `rejected_age` от всех входов |
| Цена пугает или нет | `price_shown` → `booking_started`. Если разрыв большой — проблема в цене или в её подаче |
| На каком шаге умирает диалог | Распределение `last_state` среди тех, у кого нет `booking_data_complete` |
| Ночь работает? | Тег `night_dialog` — какая у него конверсия против дневных |
| Какое объявление приносит бронь | `entry_keyword` (после внедрения `?ref=`) в разрезе `booking_data_complete` |

Через две недели эти пять цифр скажут вам о воронке больше, чем весь рекламный кабинет:
кабинет видит только начатую переписку, а бот — всё, что после неё.

## 10. Оговорка

Названия шагов и полей приведены по стандартной механике ManyChat (Flows, Custom Fields, Tags,
Keywords, Default Reply, Condition, Smart Delay, User Input, Notify Admin, Pause Automation,
Growth Tools, Recurring Notifications). Часть возможностей — в частности Recurring Notifications
и отдельные типы Growth Tools — **доступны только на платном тарифе Pro**; проверьте свой тариф
до сборки. Формулировки пунктов меню ManyChat периодически меняет, логика при этом остаётся.
